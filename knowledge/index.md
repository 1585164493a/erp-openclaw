# 知识库索引

> 给 Text2SQL / 业务分析用的结构化知识。**先读本文件，再按需读下面 1~2 篇**，不要一次全读。

| 文件 | 什么时候读 | 体量 |
|---|---|---|
| `schema.md` | 需要确认表/字段含义、表之间怎么关联 | ~110 行 |
| `metrics.md` | 问题里出现"达成率/占比/周转/交付周期/平均"等指标词 | ~60 行 |
| `traps.md` | **写 SQL 之前必读**（软删、枚举、多对多、时间窗口） | ~50 行 |
| `examples/` | 需要参考写法时按名字取（如 `share_by_channel.sql`） | 每篇十几行 |

## 三条铁律（不看别的也要记住）

1. **软删除**：几乎所有表都有 `deleted`，查询一律加 `deleted = 0`。
2. **枚举要翻译**：`status`、`customer_type` 这类数字必须转业务含义（见 `schema.md` 的枚举段）。
3. **口径先定再算**：时间窗口（自然月 vs 滚动 30 天）、分母是谁、去不去重 —— 见 `metrics.md`。

## 数据现状（用来判断问题是否可行）

- 库：`motorparts_db`，17 张表，另有两张视图
- 销量数据区间：**2026-08-23 ~ 2026-11-12**（约 6300 行日销）
- 采购单区间：2024-01-01 ~ 2026-11-11（295 单）
- 销售目标：2026-09 / 10 / 11 三个月（渠道 + 品类两个维度）
- 没有的：退货、客户满意度、市场行情、未来预测数据

## 元数据自带的字典

`meta_dict` 表本身就是一份"表用途 + 枚举含义"字典，可用 SQL 直接查：

```sql
SELECT table_name, column_name, value_code, meaning
FROM meta_dict WHERE deleted = 0 AND dict_type = 'enum';
```
