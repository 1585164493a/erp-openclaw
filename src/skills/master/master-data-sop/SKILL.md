# 主数据查询 SOP

> 主数据域管的是「**数据是什么**」—— 档案内容、字段结构、取值含义。
> 它不做分析、不做过算、不做写操作。

## 1. 元数据优先原则（本域最重要的一条）

**遇到任何不熟悉的表名、字段名或数字取值，先查元数据，绝不推测。**

| 问题 | 用哪个工具 |
|---|---|
| 系统里有哪些表？这张表是干什么的？ | `meta_schema()` |
| 这张表有哪些字段？字段类型/注释？ | `meta_schema(table="customer")` |
| 这个字段的数字取值是什么意思？ | `meta_dict(table="customer", column="customer_type")` |
| 这张表有哪些枚举字段？ | `meta_dict(table="purchase_order")` |

**为什么这条最重要**：数据库里存的是编码（`customer_type=1`），
业务含义只存在于 `meta_dict` 里。**不查就编，属于一眼假**——
例如把 `customer_type=1` 解释成"一类客户，采购量最大"，
而真实含义是 **KA商超**。

## 2. 三类主数据的查询入口

| 实体 | 工具 | 说明 |
|---|---|---|
| **商品** | `product_query` / `product_search` / `product_by_supplier` | 商品档案：编码、名称、系列、包装规格、单位、采购价、建议零售价、品类、安全库存阈值 |
| **供应商** | `supplier_query` | 供应商档案：编码、名称、联系人、信用评级、合作状态 |
| **客户** | `customer_search` | 客户档案：编码、名称、联系人、客户类型、折扣等级 |

**配额口径**：主数据查询默认只返回有限条数（各工具 `limit` 参数）。
需要全量时明确说明"当前只返回前 N 条，如需更多可调大 limit"。

## 3. 编码与字段口径

| 口径 | 说明 |
|---|---|
| **软删除** | 所有业务表都有 `deleted` 字段：`0`=有效，`1`=已删除。**查询默认已过滤 deleted=0**，回答时不必赘述 |
| **编码规则** | `product.product_code`（如 `HFS-400-01`）、`supplier.supplier_code`（`SUP001`）、`customer.customer_code`（`CUS00001`）—— 均为业务唯一编码 |
| **枚举字段** | 一律用 `meta_dict` 查含义，不要自行解释数字 |
| **金额字段** | `purchase_price`（采购价）/ `suggested_retail_price`（建议零售价），单位：元 |

## 4. 回答格式

1. **先给结论**（"查到 5 个澜溪 SKU"），再列明细
2. 明细按**编码 + 名称 + 关键字段**列出，不要把整行原始字段全贴出来
3. **引用枚举值时附带含义**（如"客户类型：KA商超"），而不是只给数字 `1`
4. 说明**返回条数与上限**（如"共 40 个客户，此处列出前 5 个"）

## 5. 常见错误（别犯）

- ❌ 不查 `meta_dict` 就解释数字编码的含义
- ❌ 凭猜测写字段名（应先 `meta_schema` 确认）
- ❌ 把主数据查询做成分析（如"哪个客户最优质"——那是需要业务规则的分析，不是档案查询）
- ❌ 在回答里泄漏 `deleted` / `create_time` / `update_time` 等技术字段，除非用户明确问
- ❌ 把 `limit` 截断的结果说成"全部"
